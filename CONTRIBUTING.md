# Contributing

Describe the problem before changing a calculation. Include a fictional or public-domain example, the settings used, the expected result and the source of that result. Remove personal birth data from issues, fixtures, screenshots and logs.

For calculation changes:

1. State the formula or tradition being implemented.
2. Add tests for boundaries and invalid input as well as a normal case.
3. Compare against an independent source where available, using identical settings. Identify comparisons that reuse Swiss Ephemeris.
4. Update the calculation reference and supported-features list.
5. Run the test suite, formatter, linter and package build described in the README.

For interpretation changes, cite the relevant text or school and distinguish traditional rules from modern interpretation. Do not add guaranteed outcomes or numerical scores without a defined calculation.

Use direct language in documentation. Describe inputs, behavior, examples and limits. Avoid marketing claims, decorative badges, invented ratings and claims that tests establish astrological accuracy.

Keep dependencies local to the project environment. New network access, telemetry, uploads or paid services need a documented reason and an explicit user choice.
